## 项目简介

Smart Tabular Analyzer 用于帮助用户理解字段结构陌生或不一致的结构化数据文件。选择 CSV 或 Excel 文件后，应用会完成数据预览、字段类型识别、常见数据质量检查、统计计算、图表生成、筛选与分组分析、基于已有数据的基础结论生成以及结果导出。

该项目是静态网站，不依赖后端服务、数据库、账号系统或构建流程，也不要求固定字段名。

## 核心功能

- 导入 CSV、`.xlsx` 和 `.xls` 文件，支持多工作表选择、中文字段名与内容，以及自动识别、UTF-8、GBK 和 GB18030 等 CSV 编码选项。Excel 中设为百分比格式的单元格按百分比显示。
- 自动跳过表头上方的标题行、说明行和空行，并在状态栏和报告中写明表头在第几行。
- CSV 读取时有疑问的行（如某行的列数少于表头）用中文写明在文件第几行，质量页显示有几处疑问、涉及几行；“数据列多于表头”“引号没有闭合”的报错也写明第几行。用分号、制表符或竖线分隔的文件被读成 1 列时会给出提示。
- 分页预览数据（每页 50 行，第一列是文件行号，跟随筛选条件），并汇总数据规模、字段构成、空值和重复行。
- 自动识别数值、分类、日期和 ID 字段，并可在需要时人工修正为数值、分类、日期、ID 或忽略。
- 报告空值及空值占比、完全重复行、基于 IQR 判断的偏大或偏小的值，以及认不出的数字或日期：质量页以“认不出的数字或日期”汇总并给出每个字段最多 3 个样例，统计表单列显示认不出的数量。
- 检查类型为 ID 的字段有没有重复值：质量页和报告为每个字段最多列出 10 个重复值，写明出现次数、所在的文件行号（Excel 的行号，或 CSV 中这条记录开始的行）以及其中有几行内容完全相同。值大多重复出现的 ID 列（例如行为日志里的用户ID）只给一句提示，不逐个列出。
- 找出 N/A、NULL、— 这类常被用来表示“没有数据”的写法（像是空值的写法）：质量页按字段列出每种写法的出现次数、文件行号，以及按空值处理后空值和字段类型会怎样变化。没确认之前导入结果完全不变；按字段逐个点“按空值处理”（或一次点“常见写法全部按空值处理”）后，这些值按空值处理，不再算作认不出的数字或日期，也不进入统计、Top 10、分组、筛选选项和编号重复检查，每条都可以撤销。原始数据、数据预览和导出的 CSV 保持原样，报告会写明哪些写法已按空值处理、哪些还没确认。
- 按字段读取带单位、万/亿和全角的数字：写成“2200元”的金额列按“元”读取，“1.2万”读成 12000，“3亿”读成 300000000，“１２３”这类全角数字读成 123。认的单位：元；kg、克、千克、公斤、斤、吨；件、个、箱、台、人、次；秒、分钟、小时、天；米、cm、mm、km；岁（拉丁字母不区分大小写）。统计表、图表标题和坐标轴、报告在字段名后写明单位，如“金额（元）”；数据预览和导出的 CSV 保留原文。质量页的“按单位读取的数字”列出哪些字段这样读取了，“像是数字的文本列”指出大多数值能读成数字、但还不够判为数值的分类字段，并给出最多 3 个读不了的值。
- 提示疑似合计 / 小计行：一行里有“合计”“小计”“汇总”“Total”这类标签，并且某个数值列的数等于它覆盖的明细行之和（误差 0.5% 以内）时，质量页和报告会列出这一行、对上的列和对应的行范围，最多列 20 行。这些行只提示、不排除，仍计入求和、平均值和偏大或偏小的值的判断。
- 列出 Excel 公式错误单元格（#DIV/0!、#N/A、#REF!、#SPILL! 等）：质量页和报告按字段写明每种错误的个数和文件行号。它们仍按空值处理，字段的空值行列表会写明哪些是公式错误。
- 提示格式不一致，只提示、不改任何结果：日期列混用写法（Excel 日期单元格、2024-05-06、2024/5/6、2024.5.6、2024年5月6日 等），列出不是主写法的行；整列只有一个值（非空值全都一样）；同一个值，写法不一样——首尾空格、只有不可见字符的格，以及只差全角半角、大小写、零宽字符或中间空格多少的写法（如 HD、ＨＤ、hd）。质量页和报告都有这三项，日期写法和写法不一样的值可以点“查看”列出所在的行。
- 查看问题行：在质量页各项计数旁点“查看”，列出它背后的行——空值、公式错误和认不出的数字或日期（按字段）、偏大或偏小的值（按数值字段）、完全重复行（按组，每组第一行标“保留”，与去重导出一致）、疑似合计 / 小计行、编号重复（全部重复值的全部行）、像是空值的写法（按字段和写法，已按空值处理的也能看）和读取时有疑问的行。每行带文件行号、一句说明和全部原始列，问题单元格高亮，每页 50 行，可在下拉框里切换类别；“导出这一类”把整类的全部行导出为 CSV（前两列是“文件行号”“说明”，同样带 BOM、中和公式前缀）。列出的行与质量页的计数出自同一套判断，基于原始数据，不随筛选变化。
- 生成描述性统计、分类 Top 10 频数、数值分布（评分等小范围整数按每个取值计数）和日期趋势（默认显示每期记录数，也可选择数值字段的平均值或求和）。
- 应用分类、数值和日期筛选，并进行分组分析（一个指标、一个分组字段，可选时间字段）。
- 在分类图和日期趋势图下方各给一句基于已有数据的结论，分别跟随该图当前选择的字段，不推断外部业务背景；趋势结论按记录数比较，并提示最后一个月或年份可能不完整；分类结论遇到取值过于分散的字段时会写明不做概括。报告里的结论与页面上的相同。
- 在浏览器中导出筛选后或去重后的 CSV，保留字段顺序并中和电子表格公式前缀。
- 导出写法统一的表：先点“检查会改哪些格”，按字段看会改写多少格、哪些格保持原值；再导出全部原始行——日期写成 YYYY-MM-DD，数字去掉单位、万/亿、全角、千分位和货币符号，清空已按空值处理的写法，去掉文本首尾空格。另可导出改动清单，逐格列出改写或保持原值的单元格（文件行号、字段、原值、导出值、处理）。
- 将分析导出为 HTML 或 Markdown；报告会记录当前应用的筛选条件，HTML 报告会嵌入当前已渲染的图表，可离线查看。

详细处理规则和数据流请参阅[架构说明](./docs/ARCHITECTURE.md)。

## 隐私说明

CSV 和 Excel 解析、筛选、分析、处理后数据导出及报告生成均在浏览器本地完成。应用不会上传或存储用户文件及生成的报告，也不会将数据集内容发送给第三方 API 或要求用户注册账号。

页面从仓库自带的 `vendor/` 目录加载固定版本的 PapaParse、Chart.js 和 SheetJS，并通过子资源完整性（SRI）校验。页面不会访问第三方 CDN 域名，上传文件的内容仍保留在浏览器运行环境中。依赖库随页面一起托管，页面加载完成后即使断网，也能分析你导入的文件；“使用示例数据”需要从站点读取示例文件，仍需联网。

```bash
git clone https://github.com/wy-data-30/smart-tabular-analyzer.git
```

然后打开：

```text
http://localhost:8000
```

## 已知限制

- 单次导入限制为 25 MB、100,000 行数据和 200 列。
- 解析和分析在浏览器主线程中运行；接近导入上限时可能暂时阻塞界面，移动设备上的影响更明显。
- 字段识别基于启发式规则，严格日期解析可能要求用户人工确认含义不明确的字段。
- 表头上方的标题行、说明行和空行会被自动跳过，从第一个非空行起最多检查 10 行。能跳过的行：只有 1 格文本，或只有 2 格文本且其中一格含冒号（如“制表日期：…”）。跳过时，状态栏和报告会写明“表头在第 N 行”。
- 识别不出表头所在行时，报错会提示删除表头上方的标题行；目前还不能手动指定表头行。
- 不支持多行表头，一个工作表里有多块表格时不支持。
- 疑似合计 / 小计行只提示、不排除，其中的数字仍计入统计；不想计入请在原文件里删除。标签要整格符合（去掉空白、结尾冒号和结尾的一个括号注释之后）：最多 12 个字的前缀加 合计、总计、小计、总和、汇总、累计（或 合計、總計、小計、總和、匯總、彙總、累計），或 Total、Grand Total、Subtotal、Sub-total、Sum（不区分大小写）。不算标签的：共计、合共、（合计）、合计（元）（含税）、合计[元]、合计【元】；前缀只是状态词的（已、未、不、无、無、非、待、是否、尚未、暂未、暂不、暫未、暫不），如“已汇总”；Sub-total 用 U+2010 连字符的写法；中间带零宽空格的写法。
- 恰好带标签的明细行可能让合计漏报：没对上的标签行只再核对一轮，所以第一条明细带标签的表，可能提示了各小计却漏掉总计。
- 表头本身仍要求每个有数据的列都有唯一、非空的字段名，Excel 表头还必须是文本单元格；空表、无表头、受保护或结构异常的工作表可能被拒绝。
- Excel 百分比格式只根据表头以下前 1,000 行判断；货币等其他数字格式不读取。
- 编号重复的值去掉首尾空格后比较，区分大小写。ID 列里的 N/A、— 这类像是空值的写法没确认时不算空值，重复出现时会作为重复值列出；在质量页按空值处理后不再列出。
- 像是空值的写法只认固定清单里的写法，而且要整格一致（去掉首尾空格、全角转半角之后）；“缺考”“未知”这类其他文字不会列出。带零宽空格（U+200B）的写法匹配不上。
- “无”“暂无”“-”“/”“NA”也可能是有效值，不包含在“常见写法全部按空值处理”里。会计格式里的「-」通常表示 0，确认前请看清楚这一列的含义。
- Excel 里的公式错误单元格（#N/A、#DIV/0! 等）导入后算作空值，并在“公式错误单元格”小节列出，不会出现在像是空值的写法列表里。不列出的：整行都是错误值的行（不会导入）、没有表头且只有错误值的列、表头和标题行里的错误。CSV 里的“#DIV/0!”只是文字：在数值列里算认不出的数字，“#N/A”算像是空值的写法。
- 带单位的数字要整格写成“数字 + 可选万/亿 + 可选单位”。`￥2200元`（货币符号加单位）、`(2200元)`（会计负数加单位）、`1.2 万`（万前面有空格）、`2200元/件` 都读不了，照旧算认不出的数字。g、m、分有歧义（4G / 5G、米还是分钟、分数还是分钱），不认作单位。
- 同一列混用单位（如 kg 和千克、kg 和克）时不做换算，整列都不按单位读取；质量页会写明出现了哪些单位、各几个。
- 字段名写“万元”、值又写成“1.2万”时，仍按元读成 12000。
- 会计格式里的「-」通常表示 0，但仍作为像是空值的写法列出，不会读成 0。
- Excel 单元格按原始值读取：用数字格式显示成 001012 的 ID 按 1012 检查和显示，数字 1012 和文本 1012 算同一个 ID。
- 格式不一致只是提示。只差全角半角、大小写、不可见字符或空格多少的写法才归为一组：华东 / 华东区、简繁（華东 / 华东）、“张 三 / 张三”（去掉中间全部空格）都算不同的值。补零和带不带时间不算不同的日期写法（2024-5-6 和 2024-05-06 10:30 都是年-月-日）。数值字段里的“1”和“1.0”不算整列只有一个值。区分大小写的 ID（如 AbC 和 aBc）会被报为写法不一样。
- Excel 里只有时间的单元格（格式为 hh:mm）是数字单元格，会读成日期 1899-12-31。
- Excel 里带时间的日期单元格（如格式为 yyyy-mm-dd hh:mm）导入时只保留日期，分析和所有 CSV 导出里都没有时间部分。
- 导出写法统一的表时不改写百分比（50%）和科学计数法（1e3），带时间的日期（如 2024-05-06 10:30）保持原值；零宽字符、全角字母和大小写不统一。
- 导出写法统一的表后，按单位读取的数字只剩数字，单位不写进表头（“金额”仍是“金额”，不是“金额（元）”）。
- 英文日期里的星期不核对：Tue, 6 May 2024 读作 2024-05-06（那天其实是星期一），导出写法统一的表时只按日期写成 2024-05-06。
- 日期列的日月顺序（日在前还是月在前）只靠会被改写的格确定时，导出写法统一的表后剩下的带时间的写法就没有了判断顺序的依据，再次导入本工具时可能读不成日期；检查表会在这一列下面提示。
- 改动清单最多导出 1,048,575 条（Excel 一张工作表的行数减去表头）。超出时只导出前 1,048,575 条，文件名和状态行会写明；检查表里的计数仍是全部。
- 用 Excel 直接打开导出的 CSV 时，Excel 会去掉 007 这类前导零，超过 15 位的数字也会丢失精度；本工具写出的是原文。
- CSV 的文件行号按文本行计算，与记事本显示的一致；数据行、读取时有疑问的行和报错写的都是这条记录开始的那一行。单元格里含换行时，用 Excel 或 WPS 打开同一个 CSV，之后各行看到的行号会比工具显示的小。
- 问题行只能在质量页查看和导出；HTML / Markdown 报告不列问题行明细，也没有汇总全部问题行的视图。
- 项目聚焦基础探索式分析，不包含高级数据清洗、预测或机器学习。
- 分析结果不会持久化；刷新页面会清除当前分析。
- 第三方库自行托管在 `vendor/` 目录；升级时需要同时替换库文件、`integrity` 值和许可证文件。
